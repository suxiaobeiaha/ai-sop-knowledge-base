# 03 · 部署方案 — 本地(P1)

> 目标:一台 Windows PC 上跑通 Dify + 本地 Ollama,验收本地问答。

## 1. 前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Docker Desktop | WSL2 后端,已启动 | `docker info` |
| Git | Git for Windows | `git --version` |
| Ollama | 已按 ROCm 调通(RX 9070 XT) | `ollama list` |
| 磁盘 | 空闲 ≥ 25GB(Dify 镜像 + 模型) | — |

## 2. 网络准备(国内)

- **GitHub**:走 `https://gh-proxy.com/` 前缀(部署脚本已内置)
- **Docker Hub**:已配置 `registry-mirrors`(2026-11-02 实测可用:`docker.1ms.run`、`docker.m.daocloud.io`;`hub.rat.dev` 返回 302 存疑;`docker.xuanyuan.me`、`dockerproxy.net` 已失效)
- **Weaviate 向量库镜像**:⚠️ `cr.weaviate.io` 会重定向到 Docker Hub,拉取需代理(见 FAQ)
- **Ollama 模型**:走魔搭(ModelScope)镜像,已走过的路径

## 3. 部署步骤

一条命令:

```bash
bash deploy/setup-dify.sh
```

脚本等价于:① 克隆 Dify(镜像通道)→ ② 生成随机 SECRET_KEY → ③ 生成 envs 配置文件 → ④ `docker compose up -d`。
首次拉镜像约 10GB,耗时取决于网络。

**日常启动/停止**(机器重启后):双击 `scripts/start-all.bat` 一键拉起(Docker Desktop + Dify 栈 + Ollama),`scripts/stop-all.bat` 停止。均可重复执行。

## 4. Ollama 接入(关键)

1. **本机 Ollama 开放监听**(Windows 环境变量,重启 Ollama 生效):
   ```
   OLLAMA_HOST=0.0.0.0:28434
   ```
   (⚠️ 不要用默认 11434:会被 Docker/WSL 的端口排除区间吞掉,见 FAQ)
2. Dify 控制台 → 头像 → 设置 → 模型供应商 → **Ollama** → Base URL 填:
   ```
   http://host.docker.internal:28434
   ```
   (Windows Docker Desktop 自动解析到宿主机)
3. 拉取并注册模型(对话模型本机已有 `lumen:14b`,嵌入走魔搭镜像):
   ```
   ollama pull modelscope.cn/Xorbits/bge-m3-gguf:Q8_0    # 嵌入,约 1.2GB
   ```
   在 Ollama 供应商页添加模型时,**模型名要填 `ollama list` 里的完整名**(如 `modelscope.cn/Xorbits/bge-m3-gguf:Q8_0`),不是短名。
4. 在"系统模型设置"里把默认对话/嵌入模型指向它们。

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| 80 端口被占用 | 改 `deploy/dify/docker/.env` 的 `EXPOSE_NGINX_PORT`,重启 |
| 镜像拉不动 | 换 registry-mirror 镜像站;或用代理环境变量重启 Docker |
| weaviate 拉取报 `registry-1.docker.io` 超时 | `cr.weaviate.io` 重定向到 Docker Hub:开代理(TUN 模式)后重试;或把 `.env` 的 `VECTOR_STORE` 换成 `qdrant`(镜像站可拉) |
| 启动后 plugin_daemon / local_sandbox / agent_backend 重启循环 | ① `find envs -name "*.env.example" -exec sh -c 'cp "$1" "${1%.example}"' _ {} \;` ② 生成 `DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN` 写入 .env ③ 注释 `dify-agent.env` 中的空 OTLP 变量 → `docker compose up -d`(setup-dify.sh 已内置) |
| 镜像站被限流(daemon 拉取报 EOF,浏览器可访问) | 免费镜像站有流量限制,拉大镜像易触发;给 Docker Desktop 配代理(Settings → Resources → Proxies,地址 `http://host.docker.internal:<代理端口>`)走代理直连 Docker Hub |
| 模型插件报 `failed to install dependencies ... no activity for 120 seconds` | 插件 pip 直连 PyPI 被墙:在 .env 加 `PIP_MIRROR_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 和 `PLUGIN_PYTHON_ENV_INIT_TIMEOUT=300`,`docker compose up -d plugin_daemon` 重建 |
| Dify 连不上 Ollama | ① 确认 OLLAMA_HOST 已设 ② 宿主机访问 `http://127.0.0.1:28434/api/tags` ③ 容器内解析 host.docker.internal |
| Ollama 绑定失败:`bind: ... forbidden` / 服务起不来 | Windows 端口排除:查 `netsh interface ipv4 show excludedportrange protocol=tcp`,若目标端口落入排除区间(常见 11434),换端口 `setx OLLAMA_HOST 0.0.0.0:28434` 并重启 Ollama,Dify 侧 Base URL 同步改 |
| 模型 OOM / 不支持 | 换更小量化版;RX 9000 系个别模型未适配,以 `ollama list` 实测为准 |
| 首次问答慢 | 正常(模型冷加载),第二次变快 |
