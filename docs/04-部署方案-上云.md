# 04 · 部署方案 — 上云(P4,待触发时细化)

> 状态:骨架版。触发条件:本地稳定运行 ≥ 2 周,且有移动端/持续运行需求。
> ⚠️ 上云是付费操作,执行前按惯例先给费用明细。

## 1. 方案比选

| 方案 | 说明 | 成本(参考) | 结论 |
|---|---|---|---|
| A 国内云轻量服务器自建 | 阿里云/腾讯云轻量,Docker 同栈迁移,备案后用域名 + HTTPS | 4C8G 约 ¥100-300/月(活动价浮动) | ✅ 推荐 |
| B 境外 VPS | 免备案,但访问慢、国内模型 API 调用不便 | 类似 | 备选 |
| C 托管 SaaS | 数据在第三方,不满足隐私 NFR-2 | — | 否决 |

## 2. 资源规格

- Dify 全套容器内存占用较高:推荐 **4C8G 起步**,8C16G 更稳
- 模型:云服务器无 GPU → 切换 **DeepSeek / 通义 API**(按量计费;月度用量预估在 P4 启动时测算,先报备再开通)

## 3. 迁移步骤(草案)

1. 云服务器装 Docker,克隆同一版本 Dify(镜像通道)
2. 数据:本机 `scripts/backup.sh` 导出 pg → 云上还原;`knowledge/` 走 git 推送
3. 模型:云上 Dify 停用 Ollama,配置云 API 供应商
4. 安全:HTTPS(Let's Encrypt)、强密码、安全组只开 80/443、SECRET_KEY 换新
5. 验证:执行 docs/03 §5 验收清单 → 切换访问入口
6. 回滚:本地栈保留 2 周不删,随时切回

## 4. 安全与合规

- 域名需 **ICP 备案**(国内服务器)
- 敏感知识条目(含密钥/商户号类)策略:**仅保留在本地数据集,不上云**
- 备份:云上同样部署 backup.sh,定期拉回本地
