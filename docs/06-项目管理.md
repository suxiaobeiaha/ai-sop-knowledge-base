# 06 · 项目管理

> 单人项目,采用迭代式:每个阶段有可验收产出,避免重文档。

## 1. WBS

| 阶段 | 任务 | 交付物 |
|---|---|---|
| P0 骨架 | 需求 / 设计 / 部署 / 知识库设计文档、目录、脚本 | 本仓库 |
| P1 本地部署 | Docker 环境、Dify 部署、Ollama 接入、验收 | 可用的本地知识库 |
| P2 首批蒸馏 | 工作域各子域首批笔记入库(技术支持/支付业务优先),检索达标 | 首批知识条目 |
| P3 持续沉淀 | 每周 2-3 条 + 复盘 | 知识库持续增长 |
| P4 上云 | 云服务器部署、迁移、安全加固 | 云上可用 + 可回滚 |

## 3. 风险登记册

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| Docker 镜像拉取失败 | 高 | 部署受阻 | registry-mirror 多备几站;gh-proxy 备用代理 |
| RX 9000 系部分模型不支持 | 中 | 换模型 / 降级 | 以实测为准,备选 qwen2.5:7b 等 |
| Docker Desktop 资源占用大 | 中 | 日常卡顿 | 不用时 `docker compose stop` |
| 知识含敏感信息泄露(上云) | 中 | 隐私损失 | 入库脱敏 + 敏感条目不上云 |
| 平台弃坑 / 停更 | 低 | 换平台成本 | 知识源独立于平台(核心设计) |

## 4. 配置管理

- `knowledge/`、`docs/`、`deploy/`(除克隆产物)、`scripts/` 全部 git 管理
- 单分支 main;提交规范:
  - `docs(域): 主题`
  - `knowledge(域): 新增 <条目>`
- 禁止入库:`.env`(含密钥)、`backups/`、`deploy/dify/`(克隆产物)
