# 02 · 总体设计

> 版本:v0.1 | 日期:2026-11-02

## 1. 设计原则

1. **知识源与索引分离**:`knowledge/`(git)是唯一真相源;Dify 是派生的检索索引。任何时刻可用知识源重建索引 → 平台可替换、迁移零风险。
2. **先本地后云**:本地跑通全流程,验证价值和模型效果,再花云资源。
3. **小步快跑**:每个阶段有可验收的产出(见 docs/06 里程碑)。
4. **Knowledge as Code**:知识条目用 Markdown + git 管理,享受 diff / 历史 / 回滚。

## 3. 技术选型

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Dify** | 开源自部署;知识库 + 工作流;官方支持 Ollama;DSL 导入导出;社区活跃 | 全套容器较重(镜像约 10GB) | ✅ 选用 |
| FastGPT | 知识库功能强 | 需 OneAPI 等组件拼装 | 备选 |
| MaxKB | 轻量 | 生态/扩展性较弱 | 备选 |
| 自研 RAG | 完全可控 | 工作量大,重复造轮子 | 否决 |

## 4. 模型策略

| 角色 | 本地(P1-P3) | 上云(P4) | 说明 |
|---|---|---|---|
| 对话 LLM | qwen2.5:14b-instruct(q4,约 9GB VRAM) | DeepSeek / 通义 API | 云服务器无 GPU |
| 文本嵌入 | bge-m3(约 2GB VRAM) | 云嵌入 API | 嵌入决定检索质量,优先效果 |
| 重排 Rerank | 不做(可选) | 可选 API | v1 用 Dify 默认检索即可 |

Ollama 拉模型慢时走魔搭(ModelScope)镜像(已验证路径)。

## 5. 知识分类体系

```
knowledge/
└── 10-工作/         职场主线(职业跳板)
    ├── 11-支付业务/   行业知识:通道、清算、合规、风控、接口
    ├── 12-技术支持/   排障方法论、沟通、SOP(核心域)
    ├── 13-研发产品/   需求、联调、工具、技术栈
    ├── 14-项目管理/   决策思路、复盘
    ├── 15-软考/       备考蒸馏(考证)
    └── 16-跨境清结算/ 跨境收单、外汇结算、合规申报
```

分类可扩展,规则见 docs/05 §1。

## 6. 能力蒸馏工作流(核心流程)

```
做事 / 学习 / 踩坑
    │  ① 触发:值得复用? 是 ↓
    ▼
写笔记(按 knowledge/_templates/笔记模板.md)
    │  ② 质量检查:一卡一主题、可验证、已脱敏
    ▼
导入 Dify 数据集(按域建知识库)
    │  ③ 检索验收:3 个测试问题命中
    ▼
git 提交 + 每周复盘(修订失效知识、回填 TODO)
```

## 7. 演进路线

| 阶段 | 目标 | 迁移机制 |
|---|---|---|
| 本地(P1-P3) | 全流程跑通、知识积累 | — |
| 上云(P4) | 移动访问、持续运行 | ① 知识源:git 推送 ② Dify 状态:pg 备份还原(scripts/backup.sh)+ DSL 导出 ③ 模型切云 API |

**回滚**:云出问题 → 本地备份随时重启,知识源在 git 无损失。
