# 01 · 需求分析

> 版本:v0.1(骨架版)| 日期:2026-11-02 | 干系人:自己

## 1. 项目背景

个人经验目前散落在:对话记录、记忆文件、代码仓库、脑子里。
**现状**:第三方支付公司技术支持工程师,常兼任研发/产品角色,有项目管理经验——涉猎广、深度不足。
**问题**:经验用完即忘、找不到、无法组合复用;广度不转化为结构,就成不了深度。
**机会**:已有本地算力(RX 9070 XT + Ollama)与开源平台(Dify),可以用工程化方式把"我会做的事"沉淀成"可检索、可问答的知识库"——即**能力蒸馏**;广度通过结构化沉淀与复用,逐步磨成专业深度。

## 2. 项目目标

- **工作主线**:支付行业 + 技术支持 + 项目管理的方法论 → 工作更轻松,积累面试/晋升素材,做职业跳板

以及:
- 本地部署 RAG 知识库:断网可用、零成本、数据不出本机
- 稳定运行后平滑迁移上云,实现移动端访问
- 建立可持续的"做事 → 沉淀 → 检索复用"闭环

## 3. 干系人与使用场景

| 干系人 | 场景 |
|---|---|
| 我(唯一用户) | ① 工作中排障/写方案时查方法论 ② 复习备考时检索知识点 ③ 面试/晋升准备时调取案例素材 ④ 移动端查笔记(上云后) |

## 4. 功能需求(FR)

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1 | 知识录入:支持 Markdown 导入/在线编辑 | 上传 md 后知识库可命中 |
| FR-2 | 语义检索问答:自然语言提问,返回带出处摘要 | 3 条测试题命中 ≥ 2/3 且引用正确 |
| FR-3 | 分类管理:按域组织知识,可按分类筛选 | 至少 3 个分类域可筛选 |
| FR-4 | 多轮追问:上下文连续问答 | 连续 3 轮不丢上下文 |
| FR-5 | 备份导出:一键备份数据 | 执行 scripts/backup.sh 生成备份文件 |
| FR-6 | 版本管理:知识源可追溯变更 | knowledge/ 每条笔记有 git 历史 |

## 5. 非功能需求(NFR)

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-1 | 可用性 | 本地全离线可用(模型/服务全本机) |
| NFR-2 | 隐私 | 知识源不经过任何第三方云服务(本地阶段) |
| NFR-3 | 成本 | 本地 0 成本;上云 ≤ ¥200/月(见 docs/04) |
| NFR-4 | 可迁移 | 本地 ↔ 云迁移 ≤ 半天;平台可替换(知识源独立于 Dify) |
| NFR-5 | 性能 | 单次问答 ≤ 30s(本地 14B 模型) |
| NFR-6 | 安全 | 含密钥/商户号的知识入库前必须脱敏(见 docs/05 §4) |

## 6. 约束条件

- 环境:Windows 11 + Docker Desktop(WSL2)
- 网络:国内直连 GitHub / Docker Hub 不稳 → 走镜像通道(已有 gh-proxy.com 实践经验)
- 硬件:RX 9070 XT 16GB VRAM → 本地模型 ≤ 14B 量化版
- 预算:上云是付费操作,选型前先给成本估算(惯例)

## 7. 需求优先级(MoSCoW)

- **Must**:FR-1 / FR-2 / FR-5 / FR-6,NFR-1 / NFR-2 / NFR-3 / NFR-4
- **Should**:FR-3 / FR-4,NFR-5
- **Could**:移动端优化、多模型对比、自动定时备份
- **Won't(本期)**:多用户协作、知识图谱、图片 OCR
