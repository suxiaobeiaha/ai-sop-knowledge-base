# 05 · 知识库设计

> 回答三个问题:知识长什么样、怎么入库、怎么保持质量。

## 1. 分类体系

```
knowledge/
└── 10-工作/          职场主线
    ├── 11-支付业务/  12-技术支持/  13-研发产品/  14-项目管理/
    ├── 15-软考/      16-跨境清结算/
```

- 每个子域 README 里维护「首批候选」清单,想到就往上加
- 新增子域规则:预期条目 ≥ 5 条才建;不足先放域根目录
- 文件名:`<主题>.md`,不用空格,一个主题一个文件

## 2. 笔记模板

模板见 [../knowledge/_templates/笔记模板.md](../knowledge/_templates/笔记模板.md)。字段说明:

| 字段 | 要求 |
|---|---|
| 标题 | 面向问题的一句话("如何 X"优于"关于 X 的笔记") |
| 标签 / 日期 / 状态 | 状态只能:草稿 / 已验证 / 已失效 |
| 背景 | 一句话说明什么时候需要这条知识 |
| 步骤 | 可复现的编号步骤 |
| 踩坑 | 现象 → 原因 → 解法 三元组 |
| 结论 | 可复用规则(检索时最常被引用的一句话) |
| 来源 | 溯源(对话 / 文档 / 链接) |

## 3. 分段与索引策略(Dify 配置建议)

- 数据源格式:Markdown
- 分段:块大小 ~500 tokens,重叠 ~10%,按标题层级分段
- 索引:高质量模式(bge-m3 嵌入)
- 检索:Top-K 3-5,先不开 rerank,命中差再调
- 元数据:用 `docs` 元数据标 `域: ai-ops` 等,便于筛选

## 4. 质量规范

**Do**
- 一卡一主题(单条可独立成立)
- 步骤实测可复现,结论有依据
- 涉及密钥 / 商户号 / 个人信息 → **先脱敏**(用 `<MCH_ID>` 等占位符)
- 写完 48h 内入库,趁记忆新鲜

**Don't**
- 复制整篇文档当一条(拆成原子条目)
- 大段图片 / 截图(文字优先,图走链接)
- 把"听说"的内容标成"已验证"

## 5. 入库 SOP

```
① 写 md(按模板)→ ② 自查(质量规范)→ ③ 导入对应域数据集
→ ④ 检索验收(3 问命中)→ ⑤ git 提交 → ⑥ 每周复盘修订
```

## 6. 知识生命周期

- **新增**:做事后即时蒸馏
- **修订**:检索发现过时 / 错误 → 改 md → 重新导入该条 → git 提交
- **淘汰**:标"已失效"并注明原因,不物理删除(留历史)
- **复盘**:每周 15 分钟,处理 TODO / 失效条目

## 7. 知识出口(一条笔记,两种用法)

| 出口 | 说明 |
|---|---|
| 检索问答 | Dify RAG,日常查方法论 / 步骤 |
| 面试 / 晋升素材 | 工作类笔记按「背景 → 动作 → 结果」复盘,天然是 STAR 案例 |
